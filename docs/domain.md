# 领域说明

训练周期会带来装备、报名和旅行支出，家庭收入与应急储备又有固定优先级。
计划日、银行价值日、比赛延期日和假设调整日可能不同，系统需要保留每次
重排的依据。金额精度、扣款状态和目标版本属于长期留存的信息。

`reference/domain.json` 保存公开的目标类型、扣款状态、触发类型和日历
精度约定。正式记录使用稳定标识，并区分业务时间（`occurred_on`、
`scheduled_date`、`value_date`）与接收时间（`created_at`、`imported_at`）。

## 不变量

- **已执行转账不可回算**：`executed` 状态的扣款是历史事实。重排只改写
  `pending`/`paused` 行；SQL 层面也用 `WHERE status IN ('pending','paused')`
  做防御性守卫。已入账资金按实际执行额（`executed_amount`）计入目标进度。
- **幂等导入**：银行流水以 `(account, external_id)` 唯一约束去重，重复
  导入返回 `duplicates` 计数，不重复入账、不重复标记扣款。
- **版本化计划**：每次重排落库一个不可变快照（画像、固定支出、目标、
  全部扣款），并记录触发原因、受影响目标与新的预计完成日。导出件附
  SHA-256 校验和，校验和只覆盖确定性内容，同一版本重复导出保持一致。

## 价值日与账期

扣款在本地时区的计划日发起（默认 21:00），按银行时区的结算日记账，
周末与节假日顺延到下一个工作日（`value_date_rule =
bank_timezone_business_day`）。月末跨时区入账因此可能落入下一个账期。

容量分配以**价值日所在账期**为准，未用完的月度可支配额度（收入 −
固定支出）**结转**后续账期——这是银行账户语义：钱不会在月末消失。
因此周末或时区顺延到次月的扣款由上月结余自然承接，只有累计结余不足
时扣款才进入 `paused`，恢复条件类型为 `insufficient_funds`，下次重排
时结余允许即自动恢复（也可手动恢复，但后续重排可能再次暂停）。

## 重排规则

1. 每个活跃目标按剩余金额（目标 − 已入账）与截止日均摊到各月末；
2. 与既有未执行扣款按序配对复用（保持行标识稳定，银行流水匹配不失效），
   多余行取消、缺失行新建；
3. 所有未来扣款按（账期、目标优先级、价值日）排序扣减累计结余，
   结余不足即暂停并记录恢复条件；
4. 预计完成日 = 已入账 + `pending` 扣款按价值日累计首次达标之日；
   超过截止日标记 `at_risk`，无足够 `pending` 标记 `unfunded`，
   已足额的目标自动 `completed` 并取消其未执行扣款。

## 已知边界

- 容量分配只在画像币种下进行；外币目标（HKD/USD）的扣款照常排期但
  不参与本币结余约束，系统不做汇率换算。
- 重排的结转起点是 `as_of` 所在账期，不追溯历史结余（保守假设）。
- 训练周期（training block）是时间轴上的标注，不直接产生财务影响，
  财务承诺一律通过目标表达。
